## 用户已批准的设计与取舍

- 三项推荐已由用户明确全部采纳：到期失权，以锁后数据库时间判定；初始 60 s 租约、10 s 独立周期心跳；资格无法确认时当前执行退让。没有把被否决候选重新写成未决。
- 每次资格操作使用独立短事务，先按提交 ID 锁当前行，再另发 NOW(3) 取得 UTC 数据库时间。claim 同事务取得新 attempts/worker_id，确认 COMMIT 后执行；后续 Worker 写入检查 RUNNING、代次、所有者与有效租约。
- 有效使用 lease_expires_at > 判定时间，扫描到期使用 <=；保证止于锁内判定点，同一已获准短事务可晚于到期提交，不能据此允许到期后新获资格。SQL 仅示意锁定后的条件写入，不能独立复制执行。
- 独立心跳覆盖准备、编译、长测试点和结果整理，独立 Session/事务不与执行路径并发共享；finalize 前停止新心跳、收束在途心跳后再验资格。60/10 是初始运行参数，不是调度、响应或恢复硬上界。
- 扫描只产生候选，修改时锁后重检当前状态、候选代次/所有者和到期；恢复 QUEUED 不加 attempts，下一次 claim 才加。确认状态事务 COMMIT 后才投递；迟到消息若遇 QUEUED 可合法领取新代次。
- finalize、明细及首次 AC 同事务；Worker 主动重试重置和失败写入也须有资格。资格拒绝与异常/提交未知分开；当前执行停止新测试点、不盲目重写或主动投递，尽力清理本代资源，不套 API 503。
- 围栏约束业务写入，不证明沙箱立即停止或物理互斥；不得误删后继资源。具体资源实例隔离交 W5-4，重试门槛/退避/恢复上界交 W5-3；本轮不调整其参数或进入实现。
- 选择代价：增加锁内检查及周期续租事务，瞬时数据库故障也可能放弃本次执行。没有采用接管成功才失权、逐点续租加发布限制或有界重连确认；现有字段足够，不新增列。
