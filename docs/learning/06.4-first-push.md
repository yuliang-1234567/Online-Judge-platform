# 06.4 首次推送与 CI 结果（2026-10-19）

1. 首次在交互提示中粘贴 token，被返回 `Invalid username or token`。随后用 `read -rsp` 读入并核对：长度40、前缀 `ghp_` 均符合经典 PAT 格式；改为经 `GIT_ASKPASS` 从权限600的临时文件读取后上传成功。结论：交互粘贴可能混入不可见字符，密码类输入先验长度与前缀再使用，用完立即删除临时文件。

2. 上传成功后仍被 GitHub 拒绝，原因是经典 PAT 只有 `repo` scope，不允许创建或修改 `.github/workflows/` 下的文件；为同一 token 补充 `workflow` scope 后推送成功。说明最小权限不是越少越好，而是按操作需要授予。

3. 推送实际数据：108 个对象、924.74 KiB。

4. 复核方确认远端 workflow `Backend checks` 的 [run 39265297466](https://github.com/yuliang-1234567/Online-Judge-platform/actions/runs/39265297466) 由 `push` 事件触发，结果为 `success`，耗时17秒。

5. 四张 Mermaid 图在 GitHub 文件页均渲染正常。验收由复核方在浏览器逐张截图确认，本记录依据该实际验收结果，不是本地推断。

AI 使用记录：AI 在复核方确认范围内起草本记录与三项挂账、执行只读核对；用户批准提交信息与挂账措辞。
待补理解：PAT 的 repo scope 为什么不包含 workflow 权限；git push -u 中 -u 的作用与 origin/main 的跟踪关系；为什么用 GIT_ASKPASS 读临时文件，而不是把 token 拼进 URL 或写进 credential store。
