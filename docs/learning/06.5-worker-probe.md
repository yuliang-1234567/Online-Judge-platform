所有探针容器均 --network none、--pull never；输入只读、输出可写，根文件系统只读，/tmp 使用 tmpfs，禁写 Python 字节码。
Dockerfile.dev 的 USER 65532:65532 是镜像默认非 root 身份；探针统一用宿主 UID，运行时 --user 1000:1000 会覆盖它。
make probe 的 -o addopts="" 也会移除 --strict-markers，因此该次运行不校验 marker 拼写。

我理解了什么：待用户用自己的话填写，尚未记录为已掌握。
哪里没懂 / 待补：本节验证的是同 UID 映射（宿主 1000 = 容器 1000）。跨 UID 映射、目录隔离、生产 Runner 设计一律留给 11/09 的 W5 复核。
未验证：Worker 内部访问 docker.sock 并创建兄弟容器、Celery/数据库链路、宿主驱动被 SIGKILL 后的孤儿回收、远端无 Docker CI。
遇到的坑与解决：没有出现非预期失败；单靠 marker 会先收集再排除，因此补充目录收集钩子，不将“排除执行”当作“不收集”。
为什么选当前方案：Python 标准库加已有 Docker CLI 即可做环境验收，暂不引入 SDK 或业务依赖；不通过也只记录失败边界，不阻塞认证切片。
