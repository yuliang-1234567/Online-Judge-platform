## 理解了什么
以下是 AI 对机制的解释，供用户独立复述，不能记作用户已理解：
- async 不会自动把 Argon2 移出事件循环；线程池执行与容量准入是两件事，取消请求也不等于停止线程。
- username 预查询不能替代唯一约束；INSERT 与 commit 都可能冲突，事务边界必须同时覆盖二者。
- JWT 只证明签发身份，当前权限仍要查库；把角色塞进 token 会推迟降权生效。
- Redis 的 INCR/过期分开写会留下中断窗口；Lua 原子性不代表整个“读配额→哈希→记失败”都原子。
- PyJWT 校验通过不等于输入类型严格正确：需核验原始 payload，bool 在 Python 中还是 int 的子类。

## 坑
- 实读已装 PyJWT 2.15.1：_validate_iat/_validate_exp 内用 int()，所以 float 可先被库接受；真实签名测试和原始 payload 类型测试均补上严格拒绝。
- 首轮测试用了恰好 15 字符的“短密码”，实际满足下限而得到 201；改为真正短于 15 的输入，422 断言保留。
- 既有 Alembic 离线测试会重置全局日志配置，后续 caplog 曾取不到告警；测试恢复本日志器捕获入口，同时断言事件存在及敏感文字不存在。
- 复查安装源码发现 Redis 异步客户端必须配异步 Retry；修正导入并用本地替身验证零重试时仍等待失败清理，不建立连接。
- 首轮 Ruff 报格式/类型参数写法问题，按 Python 3.12 语法修复并格式化；未删除测试或放宽安全断言。

## 为什么这样选
- 已批准 D1–D5：ASCII 用户名牺牲中文支持；注册密码 15–128 Unicode 码点且不规范化；Redis 故障注册 503（同时是 broker，暂停可接受）；每实例哈希 2，饱和 429 + Retry-After；IP + 小写用户名失败键不保证跨用户名总限速。
- fail-fast：没有 JWT_SECRET 时进程起不来、/healthz 也不可用；默认 CI 使用显式测试配置。生产入口保持 app.main:app。
- 密钥/连接串用 SecretStr；统一错误边界禁止原异常及请求原值流入响应/日志。独立测试 app 验证 require_admin，避免增加生产测试路由。
- 本轮只用已有 users；同一应用实例共享 PasswordContext。Lua 的实际执行与数据库行为留给 07.5b，不把合成存储测试说成实库验收。
