哪里没懂 / 待补：请用户复述为什么本地命令通过仍不能证明 GitHub Actions 通过，以及钩子的隔离环境为什么还需要单独固定 Ruff 版本。此处属于标准级配置的待理解项，不代替严格级模块的理解检查。

遇到的坑与解决：首次从根目录显式传 `--config` 时，Ruff 对 `app` 导入分组的判断与在 backend 内运行不同，报I001；去掉显式参数，按文件位置自动发现项目配置后，全量检查通过。没有为了迁就工具改动业务或测试代码。

为什么选当前方案：钩子只检查、不自动修复，提交失败时由开发者主动看 diff；不引入额外格式化工具。CI 只覆盖当前已有代码，不预先创建数据库集成、判题或前端任务；Actions 本身固定到已核对发布标签的提交 SHA。
