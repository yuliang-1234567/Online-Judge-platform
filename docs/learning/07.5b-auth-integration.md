- 实测（管理连接替身单测与完整入口，均退出 0）：pymysql.connect 保持 autocommit=True，随后执行 SET time_zone='+00:00'；SET 失败返回 RunnerError 70、保留驱动错误码并关闭连接，异常原文隐藏。
- 实测（同轮实际迁移物理连接）：MIGRATION_WORKER 在导入 Alembic 后注册 Engine connect 事件，用 DBAPI cursor 查询 @@session.time_zone，立即 rollback；成功 JSON 的 alembic_session_tz='+00:00'。监听器异常使 worker 失败；父进程拒绝非零进程退出、JSON 失败、字段缺失或非 UTC。离线用真实 worker 脚本注入查询/rollback 异常，验证失败 JSON 无成功字段且不泄露异常原文；本轮实库未触发事务异常回退。
- 实测（AST 单测及文件逐字比较）：backend/alembic/env.py 的 create_engine 同时锁定 poolclass=pool.NullPool、connect_args.init_command=SET time_zone='+00:00' 和 connect_timeout=5；该文件相对本轮快照及 HEAD 均零改动，没有为了探针改变迁移实现。
- 实测（新增且仅新增一条 UTC 集成）：应用 lifespan 创建的实际连接返回 session.time_zone='+00:00'，TIMESTAMPDIFF(SECOND, UTC_TIMESTAMP(), NOW())=0；原七条集成增至八条。
