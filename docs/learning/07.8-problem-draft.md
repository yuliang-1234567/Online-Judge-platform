## 遇到的坑与方案取舍（AI 说明，非用户独立复述）

- 413 必须早于 DTO 校验，依赖执行过晚；使用局部 route class 包装 receive，逐块累计实际字节，不信任 Content-Length，不调整全局中间件。
- FastAPI 在 body 解析层将 HTTPException 原样抛出，普通异常转换为 400；专用子类保持 413，包装器捕获后统一输出 error_response。普通异常只有绕过解析层才会到全局 500，本实现不依赖该路径。保留子类不等于可以省略包装器的统一响应处理。
- 应用测试覆盖 300KiB 超限、合法约 200KiB、无 Content-Length 多分块、声明偏小但实际超限；覆盖真实应用装配，存储仍为离线替身。
