# 06.2 最小后端与检查（2026-10-19）

目标：用 uv 锁定 Python 3.12 后端依赖，建立可本地运行和测试的 FastAPI 存活接口。

三条验收：先验证官方 PyPI 索引及实际包下载；/healthz 独立于数据库和缓存、实际返回 200；uv 锁定安装、Ruff 和 pytest 实际通过。

实现：backend/app/main.py 创建 FastAPI 应用和 async GET /healthz，返回 {"status": "ok"}；这是进程存活检查，不代表依赖就绪或任何业务功能。backend/tests/api/test_healthz.py 用 TestClient 检查状态码、JSON 类型及响应内容。当前未实现认证、数据库、Worker 或 readyz。

依赖：uv 0.13.1 使用系统 Python 3.12.3，项目限制 >=3.12,<3.13，.python-version 为 3.12，uv.lock 记录精确版本。运行依赖 FastAPI 0.147.0、Uvicorn 0.54.0；开发依赖 pytest 9.1.1、Ruff 0.17.1、httpx2 2.14.0。当前 Starlette 1.9.0 的 TestClient 优先使用 httpx2，旧 httpx 会发弃用警告，因此按已安装源码要求调整并重新验证；没有屏蔽警告。

验证（在 backend/）：
- 官方 PyPI 索引与 FastAPI wheel 下载均返回 200，SHA-256 与 PyPI 元数据一致；只用官方源。
- uv sync --locked：成功。
- uv run --locked ruff check .：All checks passed。
- uv run --locked ruff format --check .：3 files already formatted。
- uv run --locked pytest -q：1 passed，无警告。
- 实际启动 Uvicorn 后请求 /healthz 返回 200 和约定 JSON；OpenAPI 包含 GET /healthz。检查结束后发送 SIGTERM，日志确认 shutdown complete，进程退出且监听释放。

本节没有新增性能承诺。测试用例只覆盖当前存活接口，不代表业务测试或 CI 已通过；CI 在 06.4 配置。

AI 使用记录：AI 在用户批准范围内建立配置、接口和测试并运行验证；用户已批准将本节拆为 feat(backend) 后端提交和独立 docs 提交。待补理解：uv.lock 与 pyproject 的分工、存活与就绪检查的区别、TestClient 与真实 HTTP 的区别。后续小节仍按提交前审阅确认执行。

状态补充：本节代码及验证在原 V3 之前完成。原 V3 现已按用户决定结案为预期边界；本节采用后端骨架与依赖/环境文档分开提交的方式。
