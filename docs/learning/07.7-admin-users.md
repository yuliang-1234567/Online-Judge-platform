## 原理与取舍（AI 说明，非用户独立复述）

锁协议：可能减少有效管理员的更新先锁 ADMIN/ACTIVE 集合，再锁目标并读取当前值，保护跨行不变量。只锁目标或无锁 COUNT 无法替代该协议；目标查询刷新 identity map。纯晋升、纯激活不主动取集合保护锁，避免无必要的集合串行化；混合降权/禁用仍受保护。

审计原子性：服务持有同一个事务，用户更新和审计仓储只 flush；审计失败时上下文回滚前面的修改，成功退出才提交。先提交业务再补日志会留下无审计修改，因此不采用。摘要先选安全字段再截 2048 字符，不能截原始请求体。
