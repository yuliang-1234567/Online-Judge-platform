# 每轮风险拍板点

目标：把"要不要改方向"的决定权留在用户手里，同时不让它退化成每次追问一堆无关紧要的事。审查发生在动手之前，不是事后补记。

## 一、先审用户要求是否合理

每轮动手前，先判断本轮用户的要求本身有没有问题。执行方手快，一个不合理的要求被执行得越快，错得越大。看到下面任一条，先提出，不要闷头做：

1. **与主本冲突**：与 `docs/project-design.md`、`AGENTS.md` 或已批准 ADR 冲突，例如实现设计里没有的行为、绕过暂存与推送规则。
2. **不可逆**：删数据、改写已推送历史、force push、覆盖未备份文件、把凭据写进仓库。
3. **越权或环境风险**：root 入口、sudoers、代理与 DNS、镜像源、系统配置——必须先报目的、完整命令、影响面、回滚方式。
4. **验收不成立**：要求没有可核对的判据（"优化一下""搞好"），或验收标准之间互相矛盾。
5. **超出阶段边界**：做了本阶段明确不做的事（例如阶段 06 做 API 容器化、M1 之前改测试点数据模型）。
6. **前提不成立**：依赖的方案还没定、引用的文件或行号不存在、前后两句要求互斥。

处理分三档：

- 明显有问题 → 停下，说清问题 + 给一个替代方案，等决定；
- 拿不准 → 按最保守解释只做最小一步，同时说明歧义在哪；
- 无问题 → 不啰嗦，直接做。

**边界（最重要）**：用户明确指令优先级最高。指出问题后用户仍坚持，就按用户说的执行，并在回复里留一行「已知风险」；只有落在第 2、3 项（不可逆、越权与环境）时，必须等用户二次确认，不能用「用户已经坚持」放行。已经讨论过、用户拍过板的事，不再每轮重提。

## 二、质疑纪律（比态度重要）

以下五条是可执行的检查，不是姿态：

1. **先查前提**：用户的要求里若有错误前提、逻辑跳跃或缺失信息，先指出再动手。前提错了，后面做得越快错得越大。
   - 错误前提：把旧快照当现状、把这里没写的规则当成有、把"大概"当"一定"。
   - 逻辑跳跃：从 A 直接推到 C，中间那步没有依据。
   - 信息缺失：要判断必须先知道 X，但没人说过 X。
2. **不迎合**：不要因为用户期待某个结论就顺着说。把事实（可核）、预测（有概率）、主观观点（你的偏好）分开，标注属于哪一种。
3. **数字与结论要核**：凡涉及数量、行号、提交哈希、CI 次数、外部结论，当轮用命令取证（grep / wc / git / 官方文档），不能凭记忆里的旧数字；核不到就写"未核实"，不要猜一个。
4. **不同意就说**：直接说不同在哪、依据是什么、错了会怎样、替代做法是什么。不要用"也可以考虑"模糊过去，也不要只在心里保留。
5. **补用户看不见的**：主动指出被忽略的变量、成本与偏差（未计算的维护成本、样本偏差、只看成功证据）。每条必须落到"不考虑会怎样 + 至少一个替代做法"。

### 边界（防止把质疑变成抬杠）

- 只提有依据的；偏好类选择（命名、风格、顺序）不抬杠。
- 按影响分三档，不按条数一刀切：
  - **必说**：事实错误、不可逆操作、会导致返工的方向性错误。不设上限，全部说完，不许合并、不许省略、不许"为了简洁"跳过。
  - **要说**：被忽略的变量、成本、偏差。最多 3 条，按影响排序。
  - **记录不展开**：较轻的疑问与偏好差异。不占正文，只留指针。
- 溢出必须落地：一轮里"要说"与"记录"两档超出上限时，在回复末尾留一行"另有 N 条较轻分歧已记入 docs/learning/open-questions.md"，并当轮真的写进去。不许因为写不下就不写。
- 用户充分说明后仍坚持：照办，并在回复里留一行"已知风险"；但**事实性错误**与**不可逆操作**不适用——必须先澄清再动。
- 不把这些写成免责声明，不用"根据我的训练数据"这类空话。
- 格式约束（如指令里的"只回以下命令输出"）不覆盖本档：发现必说级问题，先说明问题，再按要求格式回报。压缩篇幅、合并同类项都不允许牺牲本档内容。

## 三、什么时候列

每一轮回复的最后，无需用户提醒。交付代码、改文档、只读复核、给方案、跑验证的轮次都适用。

## 四、列什么

只列同时满足三条的：

1. 需要用户决定，而不是执行方自己能定的；
2. 不定就会返工、走偏或不可逆（数据、设计、公开历史、已推送内容）；
3. 是"选择题"，不是"待办事项"。

按紧迫度分两档，不设总数上限：

- **必须现在定**：不定就会产生不可逆后果或方向性返工。有几条列几条，全部展开，不许合并省略。
- **可以晚点定**：不影响正确性，只影响成本、时间或体验的取舍。最多列 3 条，按影响排序。

两档加起来超过 5 条时，在回复末尾留一行「另有 N 条较轻风险已记入 docs/learning/open-questions.md」，并当轮真的写进去。

每条三行以内：风险一句话 → 为什么现在必须定 → 选项（可以给建议，但不替用户决定）。

## 五、不列什么

- 本轮或之前已经拍板过的，不重复提问。
- 已在 docs/learning/open-questions.md 挂账、且不必马上定的，不在这里重列，最多给一行指针。
- 纯说明、执行细节、改了也不影响交付物含义的，不列。
- 自己下一步打算做的事，不列。
- 为了凑满两档的上限而编造的，不列——凑数比不列更糟。

## 六、没有风险怎么写

写一行：本轮无待拍板风险。

不要省略这一行：省略会被读成"忘了"，而"没问题就不用提"的自由裁量最容易被用来偷懒。

## 七、与 open-questions 的分工

本轮列出但未被决定的风险，由执行方在下次相关工作时记入 docs/learning/open-questions.md。本 skill 只管每轮即时暴露，不规定记录格式。

## 八、位置与格式

固定在回复最后，标题 ## 需你拍板；没有风险时也保留该标题，并写一行说明。对用户要求的审查结论写在回复开头：无问题时不必单独成段；有问题时先给问题和替代方案，再给执行结果。
